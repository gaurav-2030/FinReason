The problem

Q: What was the revenue growth from FY24 to FY25?

  • Locate the right row and years
  • Extract with unit, scale, sign — “(6,537)” = −6,537
  • Formula: (new − old) / old × 100
  • Compute: 16.40%
Four skills in one question — one wrong digit, unit or sign gives a confident wrong answer.

Problem statement

Problem statement

Find which prompting and automatic prompt-optimization methods make LLMs most accurate, reliable and cheap at numerical questions over financial reports.

Input

A report page (table + text) and a question

Output

The number, with evidence rows and the calculation

Out of scope

Fine-tuning models; whole 300-page documents

We change only the prompt — never the model — and measure accuracy, cost and reliability.

Objectives

Objectives

  1. Compare 7 prompting strategies (direct, CoT, Self-Consistency, decomposition, Program-of-Thought, our VPSC)
  2. Test automatic optimization: DSPy (BootstrapFewShot, MIPROv2) and TextGrad
  3. Compare a small (1.7B) and a larger (8B) local model on accuracy and cost
  4. Analyse errors and robustness; test on Indian annual reports (₹ crore/lakh)

Approach 2/5

Text-based strategies — one question, four prompts

Q: Revenue from operations was ₹54,842 cr (FY25) and ₹47,114 cr (FY24). What was the growth?

Direct
Prompt: Give only the final answer line, with no explanation. Output: Answer: 16.4 No working shown → no way to check it. Only 2–11% correct for the 1.7B model.
Zero-shot CoT
Prompt: Think step by step: find the relevant numbers, write down the calculation, then compute it. Output: FY25 = 54,842; FY24 = 47,114 (54,842 − 47,114) / 47,114 × 100 = 16.40 Answer: 16.40
Few-shot CoT
Prompt: 3 worked examples (question → steps → Answer) + the same step-by-step instruction Effect: copies the format: units, signs, rounding, final line “Answer: <number>”
Decomposition (EEDP)
Knowledge: growth % = (new − old) / old × 100 Extract: new = 54,842 (FY25, ₹ cr); old = 47,114 (FY24) Decompose: 1) 54,842 − 47,114 = 7,728 2) 7,728 / 47,114 × 100 = 16.40 Answer: 16.40
More structure in the prompt → the model shows where every number comes from, so its errors become visible.

Approach 3/5

Code-based strategies — Program-of-Thought → VPSC

Program-of-Thought prompt → model code
# Put each value in a named variable, store result in ans revenue_fy25 = 54842 revenue_fy24 = 47114 ans = (revenue_fy25 - revenue_fy24) / revenue_fy24 * 100
  • Sandbox runs it → ans = 16.40; the computer, not the LLM, does arithmetic
  • On an error the traceback is sent back once (repair prompt)

VPSC — Verified Program Self-Consistency

  1. Sample 5 programs: 1 greedy + 4 at temperature 0.7
  2. Run each in the sandbox
  3. Grounding check: every number in the code must appear in the report (rescaling ×100/×1000 and constants such as 100, lakh, crore, years allowed)
  4. Majority vote over grounded programs only
  5. None grounded → vote over all executed programs
Rejected by the check
revenue_fy25 = 54482 # 54,482 is not in the report → dropped
Ablation: PoT-SC uses the same 5 programs without the check — so any gain is due to verification alone.

Approach 5/5

Experimental design

Factors

  • 10 prompt configurations
  • Qwen3-1.7B and Qwen3-8B [29] (local, Ollama)
  • FinQA (100), TAT-QA (100), Indian set (44)
  • Table as Markdown / JSON / HTML / text
  • Full page vs top-5 retrieved rows
  • Thinking mode on / off

Metrics

  • Execution accuracy (±0.5%)
  • Exact match and F1
  • Tokens per question and per correct answer
  • Latency (s)
  • Format and code-failure rate

Analysis

  • 95% bootstrap confidence intervals
  • McNemar vs few-shot CoT (Holm-corrected)
  • Accuracy by reasoning steps and evidence source
  • 8-category error taxonomy
  • Number-perturbation (memorization) test [28]
Every claim comes with a confidence interval, a paired significance test and its token cost.

Novelty

What is new

  • VPSC (ours): sample 5 programs → run them → reject programs using numbers not in the report → vote. Training-free, works on plain tables — lighter than recent verifiers [38], [39].
  • Indian calculation set: 44 multi-step questions from Titan, Asian Paints, Marico, Pidilite (₹ crore/lakh), answers computed from formulas — complements look-up benchmarks [36].
  • Manual vs automatic prompting, head-to-head, with cost and statistical tests.
  • Auditable web app: evidence rows, code, votes for every answer.
