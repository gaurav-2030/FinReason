1. Architecture (6 layers)

  • Data: loaders turn FinQA, TAT-QA and the Indian set into one Example (question, table, text, gold, steps, unit).
  • Context: table as Markdown/JSON/HTML/text; optional hybrid retrieval (BM25 + MiniLM embeddings in FAISS, fused with RRF).
  • Reasoning: prompt library, strategy engine, LLM client (Ollama/API, cache), code sandbox, grounding verifier.
  • Optimization: DSPy (BootstrapFewShot, MIPROv2) and TextGrad save optimized prompts as artifacts.
  • Evaluation: answer parser + scorer (0.5% tolerance), 8-category error taxonomy, bootstrap CIs, McNemar + Holm.
  • Presentation: one JSON line per answer → analysis tables/figures → Streamlit app.

2. Key designs to explain

DesignIn one line
VPSC5 programs (1 greedy + 4 at T=0.7) → run → keep those whose numbers all appear in the report → majority vote

ScoringWithin 0.5% of gold, or equal at gold's precision; % and fraction both accepted
DSPyChainOfThought program; metric = our scorer; 50 train / 40 dev FinQA questions
TextGradSystem prompt is the variable; critiques of wrong answers rewrite it; keep only if dev accuracy holds
ExperimentsSame 100/100/44 questions (seed 42), temperature 0, same examples; McNemar vs few-shot CoT

  • FinQA / TAT-QA: downloaded from the authors' GitHub; TAT-QA filtered to arithmetic questions.
  • Indian set: statements from Titan (AR 2024-25), Asian Paints (2023-24), Marico (FY25), Pidilite (2024-25) → rows transcribed exactly → each question has a formula → gold = formula result in the sandbox → build fails unless all 366 cells appear on the PDF page.
  • Mix: 23 percentages, 8 ratios/₹ amounts, 13 in crore/lakh/million/billion, 1 yes/no; 16 questions need 3+ steps.
  • Perturbed FinQA (88 Qs): operands changed by 10–30%, gold recomputed from the gold program — tests memorization.

4. Likely questions

Why one common Example format?
Every stage works on every dataset without special cases.
Why cache model responses?
Identical re-runs for free; long experiments can resume; VPSC reuses the PoT call.
How is model code kept safe?
AST check (only math), isolated process, safe builtins, CPU + 5 s limits; output is JSON only.
How do you prevent test leakage?
Worked examples and optimizer data come only from FinQA train/dev.
Why McNemar?
All strategies answer the same questions, so results are paired; McNemar compares only the questions where they differ.
How do you trust the Indian set?
366 cells checked against the PDFs at build time; answers computed from formulas; we re-verified 44/44 questions.
