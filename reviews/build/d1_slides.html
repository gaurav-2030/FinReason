The problem

Answering analytical questions over financial statements

Titan Company Ltd — standalone P&L (Annual Report 2024-25, p. 275)

Particulars (₹ in crore)FY 2024-25FY 2023-24
Revenue from operations54,84247,114
Finance costs767480
Changes in inventories …(6,537)(2,149)
Profit before tax4,4814,607
Profit for the year3,3353,544
Q: What was the percentage growth in revenue from operations from FY 2023-24 to FY 2024-25?

What a correct answer requires

  1. Locate the right row and both year columns
  2. Extract values with unit, scale and sign: ₹ crore; “(6,537)” means −6,537
  3. Choose the formula: growth = (new − old) / old × 100
  4. Compute: (54,842 − 47,114) / 47,114 × 100 = 16.40%

Analysts ask such questions constantly — growth, margins, ratios, CAGR, coverage. A single misread digit, unit or sign gives a confidently wrong answer.

Problem statement

What we set out to solve

Given a page of a financial report (a table plus surrounding text) and a natural-language question that needs numerical reasoning, produce the correct numeric answer with a transparent evidence and calculation trace — and determine, through controlled experiments, which prompting strategies and automated prompt-optimization methods make Large Language Models most accurate, reliable and cost-efficient at this task, for both small local and larger models, on public benchmarks and on unseen Indian annual reports.

Input

Table (rows × columns) + text paragraphs + question

Output

Number (or yes/no) in the report's units, plus evidence rows, program / reasoning and confidence

Out of scope

Model fine-tuning; span-extraction questions; whole-document (100+ page) search

FinReason · Review 1PES University · UE24AM343AB55
Objectives

Five objectives

  1. Benchmark manual prompting strategies (direct, zero/few-shot Chain-of-Thought, Self-Consistency, decomposition, Program-of-Thought) for multi-step financial numerical reasoning.
  2. Evaluate automated prompt optimization (DSPy BootstrapFewShot and MIPROv2, TextGrad): does it beat carefully engineered prompts, and at what one-time cost?
  3. Compare a small and a larger local model (Qwen3-1.7B vs Qwen3-8B; API models supported) on accuracy, tokens, latency and cost per query.
  4. Analyse failure modes and robustness: an error taxonomy, a numerical-perturbation (memorization) test, table-format and retrieval ablations, and generalization to Indian annual reports (₹ crore / lakh).
  5. Propose and test an improvement motivated by the error analysis — Verified Program Self-Consistency (VPSC) — and deliver an interactive web application with evidence and calculation traces.
FinReason · Review 1PES University · UE24AM343AB56
Research questions

Questions the experiments must answer

Research question
RQ1How much do prompting strategies change accuracy on multi-step financial questions, and which is best per token spent?
RQ2Do automatically optimized prompts (DSPy, TextGrad) outperform hand-written prompts, and is the optimization cost justified?
RQ3How do model size (1.7B vs 8B) and strategy interact — can a good strategy close the gap of a smaller model?
RQ4Where do models fail (evidence, units/scale, sign, arithmetic), and are the results robust to changed numbers and to Indian reports?
RQ5Does verifying that a program's numbers are grounded in the report (VPSC) improve over plain program self-consistency?

Every comparison uses the same questions, the same scorer and the same models — only the prompt changes — and is tested for significance (paired McNemar test, Holm correction).

Literature 2/6

Prompting strategies for multi-step reasoning

  • Few-shot prompting [9]: in-context examples, no training.
  • Chain-of-Thought [10]: exemplars show intermediate steps; gains emerge with scale.
  • Zero-shot CoT [11]: “Let's think step by step” — GSM8K 10.4 → 40.7%.
  • Self-Consistency [12]: sample many paths, majority vote — +17.9 pts GSM8K.
  • Least-to-most [13], Decomposed prompting [14], Plan-and-solve [35]: split into sub-problems / plans.
  • EEDP [8]: Elicit → Extract → Decompose → Predict for financial tables; matches or beats CoT/PoT on 4 financial datasets.
Takeaway: structure in the prompt helps, but benefits depend on model size and task — they must be measured, not assumed, for small models on financial data.

Literature 3/6

Program-aided reasoning: let Python do the arithmetic

  • Program-of-Thought [15]: the model writes Python; the interpreter computes.
  • PAL [16]: beats much larger CoT models on math.
  • Binder [34]: binds LMs to SQL / Python over tables.
  • Number checks: VeriFin [38] verifies operands against XBRL facts with a solver; DCRC [39] trains an evidence auditor. Plain PoT trusts its numbers.

Literature 5/6

Tables, retrieval and robustness

  • Table serialization [22]: Markdown vs JSON vs HTML vs text changes LLM accuracy on structural tasks.
  • BM25 [23] (lexical) + Sentence-BERT [24] embeddings in FAISS [25] (semantic).
  • Reciprocal Rank Fusion [26]: simple, strong fusion of rankers; RAG [27] grounds generation in retrieved evidence.
  • GSM-Symbolic [28]: changing only the numbers lowers accuracy → models partly pattern-match. Public benchmarks may be memorized.
  • Statistics for NLP [32]: paired tests (McNemar [30]), bootstrap CIs [31], multiple-comparison correction [33] — small test sets need them.

Literature 6/6

Domain models vs. prompting

Train a finance model

  • BloombergGPT [6]: 50B parameters, 363B finance tokens + 345B general tokens.
  • TAT-LLM [7]: fine-tuned LLaMA-2-7B (extractor → reasoner → executor) beats GPT-4 on FinQA / TAT-QA / TAT-DQA.
  • Cost: large curated data, GPU training, retraining for every new model.

Prompt + optimize a general model (our focus)

  • No training; works with any new model (e.g. Qwen3 [29], 0.6B–235B, thinking / non-thinking modes).
  • Runs on a laptop with local models → data never leaves the machine.
  • Question: how close can prompting + optimization get, and at what cost?

Research gaps

Six gaps this project addresses

1. No controlled, cost-aware comparison

Prior work reports accuracy for one or two strategies on large proprietary models; token cost, latency and statistical significance across strategies are rarely reported together.

2. Manual vs automated prompting not compared in finance

DSPy, MIPROv2 and TextGrad were evaluated on general QA, math and code tasks; we found no evaluation on financial table-text reasoning against strong hand-written baselines.

3. Small local models under-studied

Banks and analysts often cannot send filings to external APIs; how far a 2–8B model on a laptop gets with good prompting is largely unknown.

4. No Indian calculation benchmark

FinQA, TAT-QA, ConvFinQA and FinanceBench use US/Western reports. The 2026 Indian benchmarks cover filing look-up (IndFin-Bench [36]) and regulatory text (IndiaFinBench [37]), not multi-step calculation with ₹ crore/lakh, 1,00,000 grouping and bracketed negatives.

5. Errors are counted, not explained

Few studies categorize why answers are wrong or test for memorization of public benchmarks by perturbing numbers (cf. GSM-Symbolic for math).

6. No lightweight number check

PoT/PAL execute whatever numbers the model writes. Recent verifiers check operands against XBRL facts with a solver (VeriFin [38]) or train an evidence-auditing agent (DCRC [39]); we found no training-free check for plain report tables.

Proposed approach

One controlled pipeline — only the prompt changes

6 manual strategies

direct · zero/few-shot CoT · decomposition · Program-of-Thought · Self-Consistency (×5)

3 automated optimizers

DSPy BootstrapFewShot · DSPy MIPROv2 · TextGrad (trained on FinQA train/dev only)

1 new method (VPSC)

5 programs → sandbox → reject programs using numbers not found in the report → vote

Novelty

What is new in this project

  • VPSC — Verified Program Self-Consistency: Program-of-Thought + self-consistency + a training-free grounding check (every number in the code must appear in the report, allowing unit rescaling) — lighter than recent verifiers [38], [39]. Its ablation (same 5 programs, no check) isolates the effect exactly.
  • Indian calculation set: 44 multi-step questions over Titan, Asian Paints, Marico and Pidilite statements (₹ crore/lakh); gold answers computed from formulas — complements look-up benchmarks [36].
  • Manual vs automated prompting, head-to-head on the same questions, scorer and models, with one-time optimization cost reported.
  • Cost-aware, statistically tested benchmark: tokens, latency, bootstrap CIs, McNemar + Holm.
  • Diagnosis, not just accuracy: rule-based error taxonomy and a numerical-perturbation memorization test.
  • Auditable web app: evidence rows, code, trace, votes and exact prompt for every answer.

Expected outcomes

Deliverables at Review 3
