Prompt design

Prompt anatomy (shared by all hand-written strategies)

System

You are a careful financial analyst. Answer questions about a financial report using only the table and text provided.

Answer-format rules (text strategies)

Answer format: - The final answer is a single number. Unless the question asks for another unit, use the same units as the report (if the table says "in millions", answer in millions). Do not write the unit. - Write percentages as percent numbers (12.5 means 12.5%). - Use a minus sign for decreases and negative values. - For yes/no questions, answer yes or no. - The last line must be: Answer: <number>

Program-of-Thought instruction

Write Python code that computes the answer. Put each value from the report in a variable with a descriptive name, compute the result step by step, and store the final answer in a variable named ans (a number, or the string 'yes' or 'no'). Keep the report's units unless the question asks otherwise; give percentages as percent numbers (12.5 means 12.5%). Return only the code in one ```python block.

Repair prompt (after a sandbox error)

Running your code failed with this error: {error} Fix the code and return only the corrected code in one ```python block.

Few-shot: 3 real FinQA train questions, written in the same table format as the test question, shown as earlier user/assistant turns.

FinReason · Review 2PES University · UE24AM343AB59
Our method

VPSC: Verified Program Self-Consistency

Why

Programs make arithmetic exact; the remaining errors come from wrong numbers copied or invented by the model.

Grounding check

Parse the program (AST); every numeric literal must appear in the report, allowing ×100/×1000 rescaling, small counts, years and unit constants.

Controlled ablation

PoT Self-Consistency votes over the same 5 programs without the check → isolates the effect of verification exactly.

Security design

Running model-written code safely

  • Threat: generated code could read files, open sockets, loop forever or exhaust memory.
  • Defence in depth: static AST rules and a fresh isolated interpreter and builtin whitelist and CPU / wall-clock limits.
  • Output is data only: JSON with ans and the numeric variables (the calculation trace shown in the app).
  • Covered by unit tests (tests/test_sandbox.py): forbidden imports, dunder access, infinite loops.

Optimization design

Automated prompt optimization: DSPy and TextGrad

Optimization uses only FinQA train (50 / 40 questions) and dev (40 / 30 questions); the compiled artifacts are then evaluated on all three test sets exactly like the manual strategies, and their one-time cost (calls, tokens, minutes) is recorded.

FinReason · Review 2PES University · UE24AM343AB512
Retrieval design

Hybrid evidence retrieval (optional context mode)

  • Page → evidence units: one per table row (as text) and one per sentence; ids follow FinQA (table_i, text_j).
  • Lexical: BM25 [23]. Semantic: all-MiniLM-L6-v2 [24] + FAISS inner-product index [25].
  • Fusion: Reciprocal Rank Fusion [26], k = 60.
  • Context = header + top-k units in document order.

Recall of gold evidence on the full test sets (no LLM involved).

Evaluation design

Scoring rule and error taxonomy

Scoring (answers.score)

  • Correct if within 0.5% of gold, or equal to gold rounded to gold's precision.
  • Percentage questions: 12.5 and 0.125 both accepted (FinQA stores fractions, TAT-QA percents).
  • Also reported: accuracy at 1%, exact match (2 d.p.), token F1, format- and code-failure rates.
  • Parser handles ₹/$, 1,00,000 grouping, (bracket) negatives, %, crore/lakh/million words.
Error categoryRule
no_answerNo parsable answer in the output
execution_errorPoT code failed even after one repair
sign_errorRight magnitude, wrong sign (increase vs decrease)
scale_errorOff by a unit factor: 10², 10³, 10⁵ (lakh), 10⁶, 10⁷ (crore), 10⁹
rounding_near_missWithin 5% but outside the 0.5% tolerance
no_work_shownWrong, with ≤ 1 number in the output (nothing to diagnose)
evidence_errorAt least one gold operand never appears in the model's work
reasoning_errorAll gold operands appear, but the formula or arithmetic is wrong

Indian set

Why build an Indian annual-report test set?

  • All public benchmarks use US filings — no test of generalization to unseen, region-specific reports.
  • ₹ crore and lakh: 1 crore = 100 lakh = 10 million; models must convert units correctly.
  • Indian digit grouping (1,00,000) and bracketed negatives “(6,537)”.
  • Ind AS statement layouts; standalone vs consolidated statements; 10-year highlight tables.
  • Questions are new (written by us) over reports published in 2024–25, so the question–answer pairs cannot have been memorized.

Indian set

Collection pipeline and quality checks

Gold answers are computed

Each question has a Python formula, e.g. (54842 - 47114) / 47114 * 100; the gold is its sandboxed result — never typed by hand.

Built-in checks

Build fails unless all 366 transcribed cells occur on their PDF page, and every formula number occurs in the question's table/text.

Independent re-check

For this review we re-extracted every cited page with pdfplumber: 44/44 questions have all operands on the cited page (correct row and year column), and 44/44 golds recompute exactly.

Pre-processing

Table normalization and the four serializations

Markdown (default)

| in millions | 2014 | 2013 | |---|---|---| | sales | $ 5720 | $ 6205 | | operating profit (loss) | -16 ( 16 ) | 271 |

JSON records

[{"in millions": "sales", "2014": "$ 5720", "2013": "$ 6205"}, {"in millions": "operating profit (loss)", "2014": "-16 ( 16 )", "2013": "271"}]

HTML

<table> <tr><th>in millions</th><th>2014</th><th>2013</th></tr> <tr><td>sales</td><td>$ 5720</td><td>$ 6205</td></tr> <tr><td>operating profit (loss)</td><td>-16 ( 16 )</td><td>271</td></tr> </table>

Row-wise text (also the retrieval unit)

sales: 2014 = $ 5720; 2013 = $ 6205. operating profit (loss): 2014 = -16 ( 16 ); 2013 = 271.

Rows are padded to equal width, cells stripped, empty/duplicate headers named; the format is an ablation variable [22].

Derived data

Numerically perturbed FinQA (memorization test)

  • For each sampled FinQA question, every operand of the gold program is scaled by a random factor in [0.7, 0.9] ∪ [1.1, 1.3] (seed 42), keeping its decimals.
  • All occurrences in the table and text are replaced in one pass; the gold answer is recomputed by executing the gold program.
  • Questions are skipped if an operand is a year, a percentage, negative, or not written verbatim in the report → 88 of 100 usable.
  • Idea follows GSM-Symbolic [28]: a model that reasons should not care which numbers appear.

Example (STT 2009, p. 127)

by how much more is the net gains from sales of available-for-sale securities in 2009 compare to 2008?

Original: subtract(368, 68) = 300
Perturbed: subtract(272, 82) = 190

Same question text, same table layout — only the numbers change.
