The whole presentation in order: what to set up, what is on each slide, what to say, and every click of the live demo with the result you should see. Read it top to bottom while you rehearse.

Your slides are shown with a blue edge and a you tag (slides 6–9, from the work division). If you end up presenting alone, follow every card in order; nothing is skipped. T−30 MINBefore you start

  • Laptop on charger. Close other heavy apps (both models together use a lot of memory).
  • Turn on Do Not Disturb so no notifications pop up on the projector.
  • Open Terminal and start the app (leave this window open the whole time): 
    cd ~/Desktop/FinReason && bash scripts/start_app.sh
    Wait for URL: http://localhost:8501. If it says FinReason is already running, it is already up; just open the link.
  • Keep the screen awake: open a second Terminal tab and run caffeinate -d (stop it later with Ctrl+C).
  • Open http://localhost:8501 in Chrome or Safari. Check the green Ollama online pill at the top right of the Overview page.
  • Warm up both models (the first call loads a model into memory and takes longer): on the Ask page choose any Indian question, strategy CoT few-shot, click Run the pipeline. Then switch Model to Qwen3-8B and run again. Switch the model back to Qwen3-1.7B.
  • Open these browser tabs in this order so you can click across instead of navigating: Overview, Ask, Data, Compare, Results, Optimization, Errors (each is a link in the app’s top bar; open with Cmd+click).
  • Zoom the browser to about 125% with Cmd + so the room can read it.
  • Open the slides reviews/Review3/Review3_Final_Demo_Slides.pdf in full-screen. Keep this runbook on your phone or a second screen.
  • Backup: results/report.md has every table if the app ever fails.

Why answers are wrong

you60 s
Screen
Stacked bars of error categories.
Say
“For every wrong answer our code assigns one error type with fixed rules. The biggest part, about 60%, is evidence errors: the model used a wrong number or left one out. About 23% are reasoning errors, right numbers but wrong formula. About 9% are unit errors like millions versus thousands, and 4% sign errors. The grey part is Direct, which usually shows no working. Know

10

VPSC result

Hanshal60 s
Screen
VPSC vs PoT-SC: FinQA 56/56, TAT-QA 67/67, Indian 77/77; programs rejected 26/493, 0/491, 0/219; flagged 6 (6 wrong).
Say
“Our method: the model writes five programs, we run them, and we throw away any program that uses a number not found in the report. Of 1,203 programs that ran, the check rejected 26, from 6 questions. Accuracy is the same as voting without the check, because this small model usually writes the same program five times: when one is bad, all five are bad. But all 6 flagged answers were wrong. So the check is a reliable warning light: when it fires, do not trust the answer.”

Q&A
Each person answers questions about their own slides. You (Gaurav) take model size, Indian reports, cost and errors. Keep answers to two or three sentences; offer to show it in the app.

The five questions most likely to come, with short answers

QuestionShort answer
Did VPSC beat PoT-SC?No, identical accuracy, because the five programs nearly always agree. Its value is a precise warning: all 6 flagged answers were wrong. It costs nothing extra over PoT-SC.
Why only 100 questions?Compute on one laptop (about 30 hours for everything). Same fixed sample for every strategy, 95% CIs and paired McNemar tests. --n 0 runs the full sets.
Isn’t the cache cheating?It only replays an identical request, stores the original tokens and time, and the live new-table answer in the demo was not cached.
Why did the optimizers lose?Small 40-question validation set (overfitting), a long rewritten prompt that made the small model sometimes give no number (10% format failures vs 2%), and DSPy demos written by the weak 1.7B model itself.
Is running model code safe?Four layers: AST check (only math, no dunder, no open/exec/eval), a separate isolated Python process, whitelisted builtins, 5-second timeout and CPU limit. A production system should add a memory limit or a container.

Fifty more questions with answers are in section 09 of the presentation guide (FinReason_Presentation_Guide.html).
